Pages are optional. Without them, WordPress renders the site with its theme, and First is a backend.

A First app renders its own front end from `first/app/`: TSX that the compiler turns into PHP, rendered by WordPress on each request. It is one way, TSX to WordPress. The HTML matches what React would render for the same components, and no React runs on the server or in the browser.

## `first/app/`

```text
first/app/
├── layout.tsx                    wraps every page: export const metadata, default component
├── page.tsx                      /
├── not-found.tsx                 the 404 for URLs no route serves, and for notFound()
├── error.tsx                     a render error (logged; the page shows only this)
├── (site)/about/page.tsx         /about: a group adds no segment
├── notes/page.tsx                /notes?page=2, with export const search
├── notes/[slug]/page.tsx         /notes/<slug>: params.slug
├── docs/[[...path]]/page.tsx     /docs, /docs/a/b: params.path is a string[]
├── account/layout.tsx            export const guard = "subscriber"
├── api/notes/route.ts            export const access = "anyone"; export async function GET(req) { … }
└── _lib/                         never routed: colocated helpers
```

| Name | Meaning |
| --- | --- |
| `page.tsx` | A route. It may also export `POST`, `PUT`, `PATCH` or `DELETE` handlers for its URL, with `access` |
| `route.ts` | HTTP handlers only (`GET`, `POST`, …), for a URL with no page, with `access` or `signature` |
| `layout.tsx` | Wraps every page below it, outermost first. May export `guard` |
| `not-found.tsx` | At the root only |
| `error.tsx` | The nearest one above a page renders when the page throws |
| `[x]` / `[...x]` / `[[...x]]` | One segment / one or more / zero or more (last folder only) |
| `(group)` / `_private` | No URL segment / never routed |

Two files that serve one URL, a folder that shadows WordPress (`wp-admin`, `wp-json`, `feed`, …), a misspelled export (`metdata`) and a layout that wraps no page are build errors at the file, with the fix.

- Components are ordinary (async) functions. `&&`, `?:`, `??`, `.map`, `.length` and string methods work as in React.
- **Reads run as the visitor.** Every read a render makes is bound to the person viewing the page, so drafts, rows they may not read and masked fields never reach the HTML.
- `notFound()` renders `not-found.tsx` with a 404. `redirect(url, status?)` redirects (302 by default).
- `metadata` is an object or a function of the page's props: `title`, `description`, `canonical`, `robots: { index, follow }`. A layout's `title: { default, template }` wraps its pages' titles.
- `<Link href>` is an `<a>` that, once JavaScript runs, swaps only the router region (`@wordpress/interactivity-router`). `<Link prefetch>` prefetches on hover.
- `<Content value>` renders a post body through `the_content`. `<Html value>` places a literal as written and runs anything else through `wp_kses_post`.

A value a `search` field refuses (`?page=abc`) reads as absent. A `guard` is a role, `"authenticated"`, or `({ user }) => boolean`: a signed-out visitor goes to the login page, a signed-in one gets a 403.

Every HTTP handler says who may call it. `export const access` is `"anyone"`, `"authenticated"`, a role, a boolean or `({ user }) => boolean`, and the handler's reads run as the caller, like a page. `export const signature = { secret, header, scheme }` makes it a raw signed webhook: the body's HMAC is checked before the handler runs, and the handler runs as the system, so it can read what an anonymous visitor can't. A handler with neither, or with both, is a build error.

`first build` writes `first/_generated/routes.d.ts`. With it, `<Link href>` is checked against the app's routes and `PageProps<"notes/[slug]">` types `params`. Point TypeScript at First's JSX types:

```json
{ "compilerOptions": { "jsx": "react-jsx", "jsxImportSource": "first" } }
```

### Interactive components: `"use client"`

A component file under `first/components/` that starts with `"use client"` runs in the browser too. The compiler turns it into the WordPress Interactivity API: the server renders its HTML, and a small store module makes it interactive. There is no bundler and no Node at build time.

<RepoFile path="tests/fixtures/client-components/first/components/LikeButton.tsx" />

<RepoFile path="tests/fixtures/client-components/first/server.ts" />

- `useState(initial)` becomes a field of the element's `data-wp-context`. A setter takes a value or an updater.
- `onClick` and other event props become `data-wp-on--*` actions. An `await` in a handler is fine.
- Calling an `action()` the file imports posts to that action's endpoint with the REST nonce, so the caller is the visitor.
- `useEffect`, `useMount`, `useEvent` and `useRef` come from `"first/client"`, and `sharedState()` gives state every instance shares.
- npm imports, module-level helpers the browser doesn't have, and assigning state directly are build errors at the line, with the alternative.

The server HTML matches what React renders for the same component, which the parity tests check. These files come from [`tests/fixtures/client-components`](https://github.com/spacefast/zero/tree/main/tests/fixtures/client-components), which the test suite serves on WordPress and clicks in a browser. [`examples/full-site`](/examples/full-site) uses one for its cheer button.

### Stylesheets and images

```tsx
import "./global.css";                       // linked on every page that imports it
import styles from "./note.module.css";      // styles.dek is "note_dek"
import compass from "./compass.svg";         // the file's URL
```

A page links the stylesheets its layouts and the page import, each once, in import order. CSS module classes are renamed `<file stem>_<class>`, and a `"use client"` component may switch them with state. Every file is copied into the app plugin under a name hashed from its bytes and cached for a year. `@import`, a relative `url(...)`, `:global` and `composes` are build errors with the fix; binary images and fonts go in `public/`.

### On WordPress

The router answers on `template_redirect`, before the theme. wp-admin, login, `/wp-json`, feeds, robots and First's own paths never reach it. When `first/app/` exists, a URL no route serves renders `not-found.tsx`. URLs WordPress itself resolves (a post, a category archive) keep the theme until a route serves them. An anonymous visitor's page that no layout guards is cached at the edge for five minutes and purged when a row it read changes; everything else is `private, no-store`.

Without `first/app/`, nothing here loads and WordPress renders the whole site with its theme.

Every page also has a Markdown twin at the same URL plus `.md` (or with `Accept: text/markdown`), rendered as an anonymous visitor, and each HTML page links it. `/llms.txt` lists the app's pages that have no parameters and no guard. A page under a `guard` has no twin.

## From the old `pages/` renderer

The separate `pages/` renderer (`@spacefast/first-pages`, `first-pages build` and `first/pages.json`) is gone. A project that still has `pages/` beside `first.config.ts` fails to build with the move as the fix, and a host refuses a capture that carries old-renderer pages.

| Before | Now |
|---|---|
| `pages/<path>/page.tsx` | `first/app/<path>/page.tsx` |
| `load({ content })` returning queries | `await db.query.<kind>…` in the page; reads run as the visitor |
| `collectionPage("notes")` | `url: "/notes/:slug"` on the kind and `first/app/notes/[slug]/page.tsx`, which receives `item` |
| `<Show when={x}>`, `orElse(x, d)`, `count(list)` | `{x && …}`, `x ?? d`, `list.length` |
| `<RichText value>` | `<Content value>` from `"first/app"` |
| `<Island>` with a hand-written store | a `"use client"` component |
| `link("/x")` | `<Link href="/x">` from `"first/app"` |
| `generateMetadata` | `export const metadata = (props) => ({ … })` |
