`first build` writes a typed client for your app to `first/_generated/client/`. It calls the [REST API](/rest) with `fetch`, so it works in any browser and any frontend framework. Its types come from your config: a renamed column fails your frontend's type check.

On Spacefast, every First Space also serves the client at `/__first/client.js`, with its types at `/__first/client.d.ts`.

## Use it

```ts
import { createClient } from "./first/_generated/client/index.ts";

const first = createClient();
const notes = await first.notes.list({ where: { title: "Hello" } });
```

The client unwraps `data`, so `list()` returns the rows themselves.

## The README that build writes

Generated by `first build`. Typed, dependency-free, `fetch`-based. Copy this folder into
any frontend or import it by path. Don't edit it: `first build` rewrites it.

```ts
import { createClient, FirstError } from "./first/_generated/client/index.ts";

const first = createClient({ url: "https://example.test/__first/api/v1" });

const posts = await first.posts.list({ where: { tags: { has: "news" } }, orderBy: { createdAt: "desc" }, with: { author: true } });
const post = await first.posts.create({ title: "Hello" });
try {
  await first.posts.update(post.id, { title: "" });
} catch (e) {
  if (e instanceof FirstError) console.log(e.status, e.code, e.pointer); // 422 invalid_input /title
}
```

## Signing in

The client keeps the session it gets and sends it as `Authorization: Bearer` on
every request. An expired access token is refreshed once and the request retried.
Tokens live in memory, or in `sessionStorage` with `auth: { storage: "session" }`.

```ts
// Redirect to the first-identity screens (PKCE), back on redirectUri.
const first = createClient({ auth: { clientId: "app_...", redirectUri: location.origin + "/callback", storage: "session" } });
await first.auth.signIn();                  // leaves the page
const user = await first.auth.handleCallback(); // on /callback

// Anonymous visitors write as guests, and keep their rows when they sign up.
// With `guests: true`, a write that is refused as unauthenticated starts a guest session and is
// retried; a write a collection allows anonymously (create: "anyone") never needs one, so start the
// session yourself when you want the rows kept. `comments` below stands for a collection of yours
// whose create rule admits guests. The upgrade happens on the first-identity screens, so the client
// needs the same clientId and redirectUri as signIn(); upgrade() redirects and handleCallback()
// finishes it.
const guest = createClient({ auth: { guests: true, clientId: "app_...", redirectUri: location.origin + "/callback" } });
await guest.auth.guest();                                                 // role "guest", tokens held
await guest.comments.create({ postId: 1, name: "A reader", body: "Hi" }); // written by the guest
await guest.auth.upgrade();

await first.auth.signOut();
```

## Live updates

`first.posts.watch(query, onRows)` re-runs `list(query)` after every committed write to `posts`
(or to a collection the query loads with `with`). It polls every 30 seconds until a host
transport is registered with `registerRealtimeTransport`. See `docs/realtime.md` in the First repo.

Server to server, or from a logged-in page: `nonce` (from `wpApiSettings.nonce`) uses the
WordPress cookie, or pass `headers: { Authorization: "Basic " + btoa("user:application password") }`.
`auth.session()` hands out the held tokens to forward elsewhere.
