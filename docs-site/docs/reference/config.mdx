A First app is one `first.config.ts`. It imports its building blocks from `"first"` and exports `defineConfig({ ... })` as the default export.

## `defineConfig` options

| Option | What it sets |
| --- | --- |
| `name` | Project name: plugin slug (`first-<name>`), wp-admin menu, client docs. Default: the project directory name. |
| `collections` | Editorial content stored as WordPress posts, with the WordPress editor. Build each one with `collection()`. |
| `tables` | App data in SQL tables of their own. Build each one with `table()`. |
| `users` | Fields on WordPress users. Build each one with `userProjection()`. |
| `relations` | Links between collections and tables. Build them with `defineRelations()`. |
| `globals` | Key = the name used in `db.globals.<key>` and `/globals/<key>`. |
| `hooks` | Functions that run before or after a create, update or delete. |
| `actions` | Named endpoints at `POST /wp-json/first/v1/actions/<name>`. Build each one with `action()`. |
| `routes` | Custom HTTP endpoints on the site's own paths, outside `/wp-json`. |
| `jobs` | Background work that runs after the request, on Action Scheduler. Build each one with `job()`. |
| `webhooks` | Signed HTTP calls the app sends when rows change. |
| `services` | Private native forms, queued mail, publication search and server-priced checkout. |
| `files` | Private file buckets. Build each one with `files()`. |
| `uploads` | Limits for uploaded media. |
| `media` | Image sizes WordPress makes for uploaded images. |
| `locales` | The languages content is written in. Setting it installs Polylang. |
| `plugins` | Build-only WordPress plugin dependencies. |
| `admin` | Ship the optional admin screens (`first-admin`) with the build. Default `false`. |
| `use` | Plugin packages, registered in order: `use: [seo({ ... })]`. Each one's capabilities are inferred from its compiled code and granted by the committed `first/_generated/plugins.lock.json`. |

## Hooks, actions, globals, config

### `action`

`POST <prefix>/actions/<name>`; the handler's return value is the response `data`. Default access `"editor"`.

```ts
export declare function action<TInput extends ColumnsConfig, TResult>(definition: {
  input: TInput;
  access?: GateRule<InferActionInput<TInput>>;
  agents?: boolean;
  idempotent?: boolean;
  /** Only reads: the Ability is annotated `readonly` (run over GET) and implies `idempotent`. */
  readonly?: boolean;
  /** Deletes or overwrites data: the Ability is annotated `destructive`, so agents confirm first. */
  destructive?: boolean;
  signature?: { secret: EnvValue; header: string; scheme: "first" | "hmac-sha256" };
  handler: (input: InferActionInput<TInput>, ctx: HookCtx) => Awaitable<TResult>;
}): Action<TInput, TResult>;
```

### `global`

Defines a global. Fields use the column builders with the sub-field restrictions, and no `.unique()`/`id()`/`slug()`/`blocks()`; NOT NULL fields need a default. Default access: `read: "anyone"`, `update: "editor"`.

```ts
export declare function global<const TName extends string, TFields extends FieldsConfig>(
  name: TName,
  fields: TFields,
  options?: {
    label?: string;
    agents?: boolean;
    access?: { read?: GateRule<never>; update?: GateRule<Partial<SelectShape<TFields>>> };
  },
): Global<TName, TFields>;
```


### `definePlugin`

Defines a plugin in an installed package. Its hooks keep app-hook semantics; its actions, jobs and routes are registered as `<name>_<key>`, and `jobs.<key>` inside the plugin names its own. There is no capability list: the compiler infers it, and the app's lock grants it.

```ts
export declare function definePlugin<TSchema extends Schema = Schema>(definition: {
  /** A lowercase identifier, unique in the app: `"seo"`. */
  name: string;
  /** Keyed by the app's collection keys; the build checks them against the app's schema. */
  hooks?: Hooks<TSchema>;
  actions?: Record<string, AnyAction>;
  jobs?: Record<string, AnyJob>;
  routes?: Record<string, Route>;
}): Plugin;
```

### `route`

One method and path served by a compiled handler, in one transaction (`docs/config-api.md#http-routes`). Exactly one of `access` (who may call) or `signature` (an HMAC over the raw body; the caller is anonymous).

```ts
export declare function route(definition: {
  method: "GET" | "POST" | "PUT" | "PATCH" | "DELETE";
  path: RoutePath;
  handler: (req: RouteRequest, ctx: HookCtx) => Awaitable<RouteResponse>;
} & (
  | { access: GateRule<Record<string, never>>; signature?: never }
  | { signature: { secret: EnvValue; header: string; scheme: "first" | "hmac-sha256" }; access?: never }
)): Route;
```
