A TypedPress app starts at `typedpress.config.ts`. It imports its building blocks from `"typedpress"` and exports `defineConfig({ ... })` as the default export. Kinds, globals, file buckets, actions and jobs aren't options: each registers by its export, from `typedpress.config.ts` or any file under `tp/` (`export const posts = collection({ ... })`).

## `defineConfig` options

| Option | What it sets |
| --- | --- |
| `name` | Project name: plugin slug (`typedpress-<name>`), wp-admin menu, client docs. Default: the project directory name. |
| `webhooks` | Signed HTTP calls the app sends when rows change. |
| `services` | Private native forms, queued mail, publication search and server-priced checkout. |
| `seed` | Import synced content when the standalone plugin starts. Existing editorial content is preserved. |
| `uploads` | Limits for uploaded media. |
| `media` | Image sizes WordPress makes for uploaded images. |
| `locales` | Turned off for now: setting it fails the build. |
| `plugins` | Build-only WordPress plugin dependencies. |
| `admin` | Ship TypedPress Admin (`typedpress-admin`), the default admin at `/wp-admin/new/`, with the build. Default `true`; `false` leaves only classic wp-admin. |
| `publicAuthors` | Keep the site's authors public as WordPress ships them: author archives, `?author=N`, the users sitemap, author names in oEmbed and unauthenticated `/wp/v2/users`. Default `false`: closed, unless the users kind's read rule lets anyone read users. |
| `xmlrpc` | XML-RPC (`xmlrpc.php`, its RSD link and the pingback endpoint) as WordPress ships it. Default `true`. `false` turns it off: every call answers 403 and nothing advertises it, except Jetpack's own `jetpack.*` methods while its connection is loaded. |
| `pings` | Pingbacks and trackbacks as WordPress ships them: the site's Discussion settings decide whether new posts accept them and whether publishing notifies the sites a post links to. Default `true`. `false` closes them in and out, whatever those settings say. |
| `sealed` | Sealed mode: the only code that runs as a plugin is TypedPress's own plugins, the platform plugins, the `plugins` declared here (exact versions, checksums in the committed lock) and `use` plugin packages. Activating anything else is refused; anything else already loaded is reported. A host that mounts TypedPress through the build store can enforce the list before any plugin loads. Default `false`. See docs/sealed.md for what is and isn't guaranteed. |
| `runtimeSchema` | Let the running site add collections, globals and fields, each change stored there as a numbered schema version. The build declares the changes listed in `tp/_generated/runtime-schema.json`. Default `false`. |
| `frontend` | Who renders the public site. Leave it out for the theme (or `tp/app` when it exists); `false` for backend only; an external site's `https://` address to point links, previews and feeds there. |
| `output` | `"server"` (the default): `tp/app/` pages render on WordPress per request, and a page that exports `prerender = true` is prebuilt. `"static"`: every page is prebuilt, and `typedpress export` writes a site that needs no WordPress to serve it. |
| `use` | Plugin packages, registered in order: `use: [seo({ ... })]`. Each one's capabilities are inferred from its compiled code and granted by the committed `tp/_generated/plugins.lock.json`. |

## Columns

### `ref`

A reference to a row of `kind` (its `id`): the field holds the id, `with: { field: true }` loads the row in its place, and `kind` gets a list of the referencing rows named after this kind. Pass `() => kind` for a kind declared later or for the kind itself.

```ts
export declare function ref(kind: AnyCollection | (() => AnyCollection)): ColumnBuilder<"integer", number, true, false>;
```

### `integer`

Every field is required unless `.optional()`; `.default()` or `.defaultNow()` make it omittable on create.

```ts
export declare function integer(): ColumnBuilder<"integer", number, true, false>;
```

### `number`

Any finite number (a double).

```ts
export declare function number(): ColumnBuilder<"number", number, true, false>;
```

### `slug`

URL-safe identifier: `^[a-z0-9]+(?:-[a-z0-9]+)*$`, at most 200 characters, unique. With `source` (a text column of the same collection), an omitted slug is derived from it ("-2", "-3" ... until unique). At most one per collection; not allowed in sub-fields or globals.

```ts
export declare function slug(config?: { source?: undefined }): ColumnBuilder<"slug", string, true, false>;
export declare function slug(config: { source: string }): ColumnBuilder<"slug", string, true, true>;
```

A taxonomy: terms in WordPress's term tables, with term meta fields, attached to collections.


### `terms`

An item's terms of `taxonomy`: the term ids in write order (`[]` when none), kept as WordPress's term relationships. `with: { field: true }` loads the term rows, and the taxonomy gets a list of the items named after this kind. The same field `on` adds, under another name or with `.access()`, `.ui()` or `.reverse()`; the build refuses any other modifier.

```ts
export declare function terms(taxonomy: CollectionMeta<string, ColumnsConfig, false, "taxonomy"> | (() => CollectionMeta<string, ColumnsConfig, false, "taxonomy">)): ColumnBuilder<"refList", number[], true, true, false, false>;
```

## Hooks, actions, globals, config

### `query`

A server function that reads. The input is the handler's parameter type; it may not write (the build refuses a write, in it or in anything it calls), and its Ability is marked read-only. `POST` or `GET <prefix>/actions/<name>`.

```ts
export declare function query<F extends (input: any, ctx: HookCtx) => unknown>(
  options: FunctionOptions<HandlerInput<F>>,
  handler: F,
): Action<HandlerInput<F>, Awaited<ReturnType<F>>>;
```

### `mutation`

A server function that writes, in one transaction. The input is the handler's parameter type. `POST <prefix>/actions/<name>`.

```ts
export declare function mutation<F extends (input: any, ctx: HookCtx) => unknown>(
  options: FunctionOptions<HandlerInput<F>> & {
    idempotent?: boolean;
    /** Deletes or overwrites data: the Ability is annotated `destructive`, so agents confirm first. */
    destructive?: boolean;
    /** Signed webhooks: the caller proves the request with an HMAC instead of an access rule. */
    signature?: { secret: EnvValue; header: string; scheme: "typedpress" | "hmac-sha256" };
  },
  handler: F,
): Action<HandlerInput<F>, Awaited<ReturnType<F>>>;
```

### `global`

Defines a global, named by its export: `export const settings = global({ ... })`. Fields use the column builders with the sub-field restrictions, and no `.unique()`/`slug()`/`blocks()`; a required field needs a default. Default access: `read: "anyone"`, `update: "editor"`.

```ts
export declare function global<TFields extends FieldsConfig>(
  fields: TFields,
  options?: {
    label?: string;
    ui?: GlobalUi;
    agents?: boolean;
    access?: { read?: GateRule<never>; update?: GateRule<Partial<SelectShape<TFields>>> };
  },
): Global<string, TFields>;
```

### `adminScreen`

A TypedPress Admin screen, named by its export: `export const pendingOrders = adminScreen({ ... })` is `/wp-admin/new/screens/pending-orders` and a wp-admin page. One React component draws it in both admins; its actions run as Abilities, which check each action's own `access` (docs/admin-screens.md).

```ts
export declare function adminScreen<
  F extends string,
  TSource extends AnyAction,
  const TActions extends readonly AnyAction[] = [],
  TSubmit extends AnyAction = AnyAction,
>(definition: AdminScreenDefinition<F, TSource, TActions, TSubmit>): AdminScreen;
```

### `adminWidget`

Declare a reusable dashboard widget backed by a readonly action.

```ts
export declare function adminWidget<A extends AnyAction>(definition: AdminWidgetDefinition<A>): AdminWidget;
```

### `adminDashboard`

Declare a custom admin dashboard (or override the default Home dashboard with `home: true`).

```ts
export declare function adminDashboard(definition: AdminDashboardDefinition): AdminDashboard;
```

### `definePlugin`

Defines a plugin in an installed package. Its hooks keep app-hook semantics; its queries, mutations and jobs are registered as `<name>_<key>`, and `x.enqueue()` on one of its jobs queues it. There is no capability list: the compiler infers it, and the app's lock grants it.

```ts
export declare function definePlugin<TSchema extends Schema = Schema>(definition: {
  /** A lowercase identifier, unique in the app: `"seo"`. */
  name: string;
  /** Keyed by the app's collection keys; the build checks them against the app's schema. */
  hooks?: Hooks<TSchema>;
  actions?: Record<string, AnyAction>;
  jobs?: Record<string, AnyJob>;
}): Plugin;
```

## Errors

### `job`

A background job. The input is the handler's parameter type. `every: "1h"` also runs it on that repeat (s, m, h, d or w; at least a minute), with no input.

```ts
export declare function job<F extends (input: any, ctx: JobCtx) => Awaitable<void>>(
  options: { retries?: number; agents?: boolean; every?: `${number}${"s" | "m" | "h" | "d" | "w"}` },
  handler: F,
): Job<HandlerInput<F>>;
```

A job Action Scheduler runs on a five-field cron schedule in UTC: `cron("0 3 * * *", async () => { ... })`.
