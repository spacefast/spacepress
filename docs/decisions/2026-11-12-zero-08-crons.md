# Zero 0.8 crons stay a Spacefast host feature

## Problem

77 live 0.8 Spaces declare `sf.jsonc` crons (103 entries; production read replica, 2026-11-12).
Each cron is `{ key, path, schedule }`. The Spacefast host runs it from a wp.cloud crontab entry
(`runtime/engine/entrypoints/cron.php` in the monorepo), which sends a `GET` to `path` through
normal routing. It adds `x-spacefast-cron`, and `Authorization: Bearer <CRON_SECRET>` when the
Space declares that variable. `first migrate app --from zero-0.8` refused the `crons` key, so
every one of these Spaces had to be ported by hand.

In 74 of the 77, every cron path is an exact 0.8 endpoint path. The matches by endpoint shape are
GET + write 85, GET + read 15, POST + write 2.

## Decision

The converter carries `crons` unchanged in the candidate's `sf.jsonc` when every entry's `path`
names something the candidate answers with GET at the same path: a converted GET endpoint (now a
v2 route) or a carried static file. Any other entry is refused with `Z08_OMITTED_CRON` at
`/sf.jsonc/crons/<i>`. This includes the POST-only matches, which the host's GET never reached.

First adds no scheduling surface. The host keeps the crontab, the frozen crons slice, plan
allowance and `sf crons list/run`. A v2 route already receives every request header, lowercased,
in `req.headers`, and reads variables through `process.env`.

## Rejected

- **A `schedule` option on First jobs or routes, run by WP-cron or Action Scheduler.** This is
  new product surface and needs an owner ruling. It would also bypass the billed cron accounting.
  WP-cron fires on traffic only, unless something ticks it, and the owner's rule forbids adding a
  tick.
- **Refusing every cron.** That leaves 77 Spaces on a manual port for a feature the host already
  runs unchanged.

## What the host must do

- Read `CRON_SECRET` for a v2 version as well. `_stattic_cron_secret()` reads only
  `/functions/config.json` and `/zero/config.json`, while a v2 version keeps its variables in
  `.zero-compiled/variables.json`.
- Dispatch the cron path to WordPress for a v2 version, the same as hosted route serving.

## Open for the owner

- Whether crons stay a host feature for First apps permanently, or First later gets a portable
  schedule for self-hosted WordPress. Recommendation: host feature now; a portable schedule only as
  its own ruling.
- A cron-targeted writing GET that never checks `CRON_SECRET` can be triggered by any visitor, as
  it could on 0.8. The converter carries it unchanged.
