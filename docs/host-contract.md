# Host contract

A host compiles First apps itself and mounts them into WordPress: Spacefast is one. This page is
everything such a host may rely on. Anything not listed here is First's internals: a host that reads
generated files, requires runtime files by path or calls other `First\` classes breaks when they change.

## Versioning

Every hosted manifest (`manifest.json` of a `compile-sources` tree, format `first.hosted.v1`) carries an
integer `hostContract`. It changes only when something below changes incompatibly for a host. Additions
don't change it. A host refuses a compiled tree whose `hostContract` it doesn't know, rather than serving
it on assumptions.

## Uploads

`compile-sources <sources> <new-output> <assets> [previous-output]` takes a captured source bundle:
`first.source-bundle.v1` (`app.first.json`, `vendor.first.json`, `manifest.json`), and, for clients
released before the rename to First, `zero.source-bundle.v1` (see [Deploy on Spacefast](spacefast-deploy.md)).
`previous-output` is the tree of the version being replaced: its snapshot is the migration baseline.

A client released before the rename (the hosted MCP server 0.9.0) uploads the raw project instead of
a capture: `zero.config.ts` at the root, the relative modules it imports and `public/`. A host may
pass that directory as `<sources>` to `compile-sources` or `compile-to-store`, or capture it first
with `first::host::sources`; First captures it as the 0.3.0 compiler did and compiles that capture. Refused: an npm import (a host
installs no packages; the owner publishes from the CLI), TSX pages (`pages/` or `zero/pages.json`),
and a tree that also holds `first.config.ts` or a capture.

## Manifest

Besides `format`, `hostContract`, `compiler` and the platform versions (`wordpress`, `php`, `requires`):

- `summary`: `{name, collections, tables, actions, identity, admin}`, what a dashboard shows about the app.
- `routes`: `[{method, path}]`, the app's HTTP routes outside `/wp-json`, and `pagePaths`, its pages (GET
  and HEAD). Hand any request whose path matches to WordPress, whatever its method, after trimming one
  trailing `/` and treating HEAD as GET. Paths use `:name` for one segment and a final `*name` for the
  rest.
- `host`: the names below, as data.

## Lifecycle

See [Spacefast host checklist](spacefast-host-checklist.md) for what one host changes to meet this.

Builds come from the build store: `first compile-to-store <sources> <store> <assets> [previous-build]`
writes one and prints its id (see `docs/decisions/2026-11-07-build-store.md`). `Loader::load` mounts store
builds only; a `compile-sources` tree is for hosts that mount it themselves and is not part of this
contract. The compiled app tree's `manifest.json` (under `app/<hash>/`) is the manifest above.

1. Select the build for the request, then call `Loader::load` before WordPress initializes. It mounts
   the runtime, identity when the app needs it (or `users: true`), the app and the admin plugin. `first/app/`
   pages render from the app plugin.
2. Before exposing a new version, call `Loader::initialize` once. (It does not take the schema check's
   `--drop` confirmations yet: a version that drops data is refused there until it does.) It brings this site's storage up to
   the build (including the one-time upgrade of a site that ran a build from before the rename), applies
   pending migrations forward only, schedules identity maintenance, seeds content, and writes the ready
   marker. A ready build returns its receipt and changes nothing.
3. Rollback is selecting an older ready build: no migration runs, and the older build reads the newer
   schema's data.
4. Run `wp first jobs tick` on a schedule. It does one bounded pass of the site's background work and
   prints `{processed, failures, outboxDispatched, requeued, receiptsExpired, remaining}`. Run it again
   while `remaining` is true. It exits non-zero when it could not run. It takes the same locks as
   WordPress's own runners: it claims Action Scheduler actions before running them and runs WP-Cron
   events under core's `doing_cron` lock, so overlapping ticks, or a tick beside `wp-cron.php` or
   Action Scheduler's runner, run each action and event once.

### Reserved paths

| Path | What |
|---|---|
| `/__first/*` | First's HTTP API (`/__first/api/v1/*`): kinds, globals, actions, files, `/me`; served before the theme, outside `/wp-json`. Route it to WordPress and never cache it: every answer is `Cache-Control: private, no-store` with `Vary: Cookie, Authorization`, except file streams |
| `/identity/*` | First Identity's issuer and pages, when the app mounts identity |
| `/wp-json/first-identity/v1/*` | First Identity's REST API |
| `/wp-admin/new/*` | First Admin, unless the app sets `admin: false`: served by wp-admin's `admin.php?page=first-admin`. Apache applies the plugin's `.htaccess` rule; any other server must send a path that is not a file to WordPress's `index.php`, which redirects it to `admin.php?page=first-admin&p=<route>` |
| `/first-admin/*` | the admin's earlier address, redirected to `/wp-admin/new/*` |

The app API is `/__first/api/v1`; actions are `POST /__first/api/v1/actions/<name>`. The generated client is a file of the compiled tree (`client/client.js`); the host chooses the URL it serves it at.

### Mount and lifecycle

| Call | When |
|---|---|
| `First\Loader\Loader::load($root, $build, $options)` | before WordPress initializes, with the build the host selected for this request |
| `First\Loader\Loader::initialize($root, $build)` | once per build per site, before the host exposes it: storage upgrades, migrations, identity maintenance, the content seed |
| `First\Loader\Loader::sealed($root, $build)` | a sealed build's plugin allow-list, or null; with `Loader::allowedPlugins` and `Loader::keepUnlisted` in the host's own early code, before WordPress reads its active plugins |
| `First\Loader\Store::gc($root, $keep)` | after the host deletes a version: keeps exactly the builds it still serves |

### Hooks a host implements or listens to

| Hook | Kind | What |
|---|---|---|
| `first_mail_transport` | filter | delivers `mail.send` messages; without it, the app's mail is refused |
| `first_purge_urls` | action | the root-relative URLs a committed content write changed, for a host's page cache |
| `first_private_probe_url` | filter | the URL the private-files probe fetches, when the public URL is not reachable from the server |
| `first_identity_providers` | filter | OpenID Connect sign-in providers First Identity offers |
| `first_identity_rest_cookie_auth` | filter | lets the identity session cookie authenticate the app's REST API (a host serving its own frontend) |
| `first_identity_session_cookie_aliases` | filter | other cookie names whose session a migrated site keeps |
| `first_fetch_allow_address` | filter | allows an outgoing `fetch` to an address First denies by default |
| `first_runtime_loaded` | action | the runtime has booted; register commands and seams after it |

### Live updates

| Name | What |
|---|---|
| `first_realtime_changes` | WordPress action fired once per committed transaction with its change notice `{id, at, changes: [{collection, ops, ids}]}` |
| `First\Realtime\Publisher` | PHP interface a host implements to send each notice to its realtime transport (`First\Realtime\Module::publish`) |
| `First\Realtime\Module::shared($notice)` | the notice with the ids of collections not every visitor can list set to null, for a room every visitor shares |
| `__firstRealtime` | the page-wide registry on `globalThis` that every generated client on a page shares; a host script calls `registerRealtimeTransport` from the client to set it |

### Background work

`wp first jobs tick [--limit=<1..100>] [--budget-ms=<ms>]`

### Sealed mode

When the app sets `sealed: true`, the hosted manifest and the build manifest carry `sealed`: the plugin directory names that may load (First's own, the platform pins, and the plugins the config declares). The key is absent when the app isn't sealed. First itself only refuses new activations and reports what else is loaded, because WordPress loads drop-ins, must-use plugins and active plugins before First's app plugin. A host that wants the list enforced does it in its own early code (a must-use plugin of the host's, or `sunrise.php`): it filters `option_active_plugins` with `First\Loader\Loader::allowedPlugins($active, $sealed)`, keeps the hidden entries stored with `First\Loader\Loader::keepUnlisted($new, $stored, $sealed)` on `pre_update_option_active_plugins`, ships no must-use plugin or drop-in beyond its own, and defines `FIRST_SEALED_ENFORCED` so the app reports `enforced: "host"`. `allowedPlugins` never passes `vip-block-data-api` or `vip-decoupled-bundle`, whatever list it is given: each serves stored content around the app's read rules. Nothing changes for sites that don't serve a First app. docs/sealed.md has the example.

### Table prefix

First puts every table under WordPress's `$wpdb->prefix` and never changes it. App tables are `{prefix}first_<table>`, system tables `{prefix}first__<name>`, identity tables `{prefix}first_identity_<name>`. The host owns the prefix: a host that binds several apps to one database gives each its own prefix before WordPress loads. An app's `existingTable` must be under that prefix (and not WordPress's, First's or Action Scheduler's own table, nor under another site's longer prefix, which need not end in `_`), or the Space's own Zero 0.8 table `sf_<space>_<table>_<10 hex>` with the converter's digest of that Space id and table name. The Space id comes from the host: `spacefast_content_space_id()` when it exists, else the `FIRST_SPACE_ID` constant defined before WordPress loads; on a `sfz_<24 hex>_` prefix it must also be the Space that prefix was made from. With neither, no 0.8 table binds. The longest name First adds after it is 29 characters, so a prefix may be at most 35 characters.
